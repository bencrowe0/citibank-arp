# CLAUDE.md

Citibank Applied Research Project - earnings materials in, DeepSeek-powered structured BUY/HOLD/SELL predictions out, calibrated against actual stock price outcomes.

## Architecture

**6 issuers** (`jpm`, `bank_of_america`, `boeing`, `disney`, `target`, `netflix`) across 4 sectors - Financials, Media/Communication Services, Industrials, Consumer/Retail. Four scored layers, blended into one signal:

- **Micro** (`report_pipeline.py`, `run_reports.py`) - the company's own earnings materials (press release + presentation + transcript, bundled into one LLM call per quarter). Core layer; everything else adjusts it.
- **Macro** (`llm_macro.py`) - FOMC minutes, scored once per meeting, reused across every company/quarter whose `report_date` falls after that meeting (cached under `outputs/macro/results/`).
- **News** (`llm_news.py`) - a **pre-earnings market-expectations digest** per company/quarter, sourced from free outlets (CNBC, Yahoo Finance), stored under `docs/news/<issuer>/<document_id>.txt` with source URLs + dates inline. **Every source article is dated strictly before `report_date`** (hard rule - an earlier version leaked post-earnings reaction language; see leakage fix below). Scores how stretched/depressed market expectations were heading into the print, not sentiment about results. Backfilled (2021-2024) quarters have no news digest - known gap, not a bug.
- **Quant** (`quant_layer.py`) - deterministic, yfinance-only, zero-LLM-cost composite of price momentum, EPS surprise, and a macro-numeric sub-component (`^TNX`, `^IRX`, `^VIX`), plus optional FRED Fed-data ablation (`DFF`, `T10Y2Y`, key-free `fredgraph.csv`, cached to `data/quantitative/fred_cache/`). Never earns blend weight (below).
- **Blend** (`blend.py`) - weighted sum of the four layer scores, then `hold_upper`/`hold_lower` thresholds derive BUY/HOLD/SELL. `DEFAULT_WEIGHTS = (0.8, 0.0, 0.2, 0.0)` (micro/macro/news/quant) - pooled-LOOCV-selected, reconfirmed by every later sweep (see History).

Micro/macro/news share one prompt (`prompts/llm_analysis_prompt_template.md`), differing only in `{{REPORT_TYPE}}`/`{{REPORT_TEXT}}`. Quant is pure arithmetic, no LLM call.

## Manifest schema

`manifests/<issuer>_reports.json` - each report entry has a `documents` list: `[{"doc_type": "Press Release", "source_pdf": "..."}, ...]`. Composition varies by issuer/era (e.g. Netflix is always 1 doc; Disney backfill is press release + transcript, 2 docs; JPM/BAC backfill to 2021 is press release + presentation). `report_pipeline.build_bundle_text()` concatenates a report's documents into one labeled text block per quarter.

Long filings (10-K/10-Q, JPMC's earnings supplement) live under `docs/<issuer>/filings/` but are **intentionally excluded** from every layer - too dense, matches the group's "too financy" feedback.

## Dataset naming convention

Every scored source document lives under **`docs/<issuer>/CY<FY>-Q<FQ>/`**, where `CY<FY>-Q<FQ>` is the **fiscal period being reported** (from manifest `fiscal_period`, e.g. `FQ1 2026` -> `CY2026-Q1`), NOT the calendar quarter of the release date. Filenames stay issuer-native; only the folder is normalized. Excluded long filings go under `docs/<issuer>/filings/`. Result artifacts: `outputs/<issuer>/results/<TICKER>_FQ<Q>_<YEAR>.json`. Any future backfill must follow this scheme.

## Running the pipeline

See [README.md](README.md) for micro-layer run commands. Macro/news/blend/eval/backtest:

```powershell
python llm_macro.py                         # score all FOMC minutes (cached, idempotent)
python llm_news.py                          # score all pre-fetched news digests (cached, idempotent)
python quant_layer.py                       # score all quarters' quant composite (free, cached, idempotent)
python blend.py <issuer>                    # blend micro+macro+news+quant for one issuer's quarters
python -m eval.run_eval                     # calibrate threshold + blend weights, pooled across ALL issuers
python -m eval.run_eval --issuers jpm,bank_of_america   # per-sector experiment
python -m experiments.weight_threshold_sweep   # fine grid + asymmetric thresholds + Fed ablation + significance test (ACCURACY objective)
python -m experiments.pnl_weight_threshold_sweep   # same grid, TOTAL-RETURN objective on the overnight gap (P&L, not accuracy) + Deflated Sharpe Ratio
python -m experiments.pnl_sweep_robustness_check   # skew/kurtosis-filtered + coarse-grid follow-up to the P&L sweep's PSR finding
python build_cost_ledger.py                 # rebuild outputs/global/summary/api_cost_ledger.csv from existing artifacts (no API calls)
python backtest.py                          # P&L backtest of the LLM's overnight-gap trades, net of costs (equity curve + direction breakdown)
python backtest.py --sheet export.csv       # score every HUMAN rater from a group-sheet CSV export on the identical strategy
```

`run_reports.py` also takes `--prompt <file>` (test an alternate prompt without touching the default), `--ensemble N` (average N repeat runs per document), and `--variant <label>` (writes to `outputs/<issuer>_<label>/`, never overwrites canonical). `eval.run_eval --issuers <issuer>_<label>,...` evaluates a variant folder (macro/news lookups auto-resolve the variant label). `compare_runs.py <a> <b>` diffs two results folders, optionally against ground truth.

## Two distinct threshold concepts - do not conflate

- `hold_upper` / `hold_lower` - thresholds on the LLM's **sentiment score** (-1..+1), used to derive a prediction.
- `outcome_upper` / `outcome_lower` (`eval/outcomes.py`) - thresholds on the stock's **actual forward return**, used to derive the ground-truth label a prediction is checked against.

Never reuse the `hold_*` names for the outcome-side threshold or vice versa.

## Current state (N=131, pooled across all 6 issuers)

- **5-day forward return (default ground truth, `eval/outcomes.py`, ±3% close-to-close):** pooled LOOCV accuracy **0.466** (default=tuned) vs a majority-class baseline of **0.382** - significant (binomial p=0.030, 5,000-shuffle permutation p=0.0014). Point estimate is lower than an earlier N=78 read (0.54, partly small-N optimism, partly a thinner backfilled document set) but this is the more convincing result because significance comes from N + a proper null, not a bigger number.
- **The blend weights/thresholds are not an overfit.** A 113,344-combination sweep (`experiments/weight_threshold_sweep.py`, fine grid + asymmetric thresholds + 4 quant/Fed variants) lands back on the exact hardcoded default `(0.8, 0.0, 0.2, 0.0)` at `±0.25` every time, and every LOOCV fold independently agrees. **Macro, quant, and real FRED Fed data (`DFF`, `T10Y2Y`) all earn zero blend weight** - tested rigorously, a stable negative, not hidden.
- **Per-sector calibration overfits.** Financials (N=26) shows a possibly-real tuned-vs-default gap; Industrials and Consumer/Retail (N=13 each) show tuning actively hurting. Pooled remains the default methodology.
- **Ground truth choice changes everything for the overnight window.** The group sheet's own metric is the close-to-OPEN overnight gap at `Settings!B3`=2% (`eval.outcomes.fetch_forward_return(exit_on_open=True, window_trading_days=1)` reproduces it exactly). At B3=2 the labels are ~69% FLAT, so **raw accuracy provably cannot beat the always-FLAT baseline (0.687) at any threshold** - the strongest layer only correlates at r≈0.22 vs the r≈0.45 needed. This is a property of a weak-but-real signal on a heavily-skewed 3-class problem, not a fixable modelling gap (confirmed by sweeping B3 ∈ {1,1.5,2,2.5,3}%). **Balanced accuracy** (fixed 1/3 floor regardless of skew) is the correct metric on skewed windows: a skew-aware, news-heavy LOOCV-tuned model scores 0.498 vs 0.333 (p=0.0012, significant) on the overnight gap; the untouched 5-day-optimized default also clears 0.44-0.50 on both windows without retuning. Do not retune `outcome_upper/lower` to rebalance labels - that fits the label definition to the model, worse than tuning `hold_*`.
- **For a trading tool, P&L (not accuracy) is the right scorecard - the headline finding.** `backtest.py` models the overnight-gap strategy (BUY→long into report-date close/exit next open, SELL→short, HOLD→no trade), net of costs. The deployed model (untouched 0.8/0.2 weights, no P&L tuning): 44 trades of 131 prints, **total return +173% ($1→$2.73)**, hit rate 59%, Sharpe/trade 2.48, max drawdown 6.5%, only 4/44 trades wrong-direction (rest are correct or ~breakeven flat bets). Beats always-long (-16%) and always-flat (0%). Robust to costs (+129% at 50bps vs deployed 10bps). So the same model that *fails* overnight raw accuracy (0.55 vs 0.69 baseline) *wins* the money test, because 3-class accuracy penalizes a flat-bet the same as a wrong-direction bet, which P&L does not.
- **P&L is now the primary sweep objective going forward, not accuracy** - `experiments/pnl_weight_threshold_sweep.py` reruns the identical 113,344-combo x 4-quant-variant grid as the accuracy sweep, but selects on **total return** (order-invariant, computed via a log-space sum so the whole grid scores in one vectorized pass - no per-combo refit or price refetch) instead of avg-P&L-per-trade, which would reward cherry-picking a handful of lucky trades. Winner: weights `[micro=0.2, macro=0.0, news=0.75, quant=0.05]`, thresholds `(0.15, -0.05)` - a much heavier news weight and tighter/asymmetric bands than the accuracy-tuned default, trading 105/131 prints (vs the deployed default's 44). Pooled LOOCV total return **191.64%** beats the deployed default's 172.75% (self-check: the deployed combo run through this script's own P&L math reproduces `backtest.py`'s 172.75%≈172.62% exactly), and a 5,000-shuffle permutation test on the winner is significant (p=0.017). **Not yet promoted to `blend.py`'s `DEFAULT_WEIGHTS`** - candidate only, pending review.
- **The P&L winner's Sharpe should not be trusted at face value - Deflated Sharpe Ratio (DSR) is 0.02, not the raw 2.9.** Bailey & Lopez de Prado's DSR corrects Sharpe for (a) how many combos were searched (453,376 trials across the 4 quant variants) and (b) the winning combo's own trade-count/skew/kurtosis. Its trade-return distribution is heavily skewed/fat-tailed (skew=2.57, kurtosis=12.4 - a few outlier trades doing the work), and its raw Sharpe (2.9) doesn't even clear SR0 (3.74, the expected max Sharpe achievable by chance alone given that many trials) - PSR=0.02 means ~2% confidence the Sharpe is real skill, not luck. **Two follow-up levers were tried in `experiments/pnl_sweep_robustness_check.py` and both failed to raise PSR**: (1) filtering to only tame-looking combos (|skew|<1, kurtosis<6) post-hoc still gets scored against the full 453k-trial SR0 since that correction is about trials *searched*, not the one you *keep* - filtering cost Sharpe (2.9→1.44) for zero PSR gain (still 0.0); (2) cutting to the coarse production grid (453k→2,016 trials, a 200x reduction) barely moved SR0 (3.74→3.66, since it grows ~logarithmically with trial count) and the coarse winner's own Sharpe fell too - still PSR=0.0. **Conclusion: PSR>0.9 (the standard Bailey/Lopez de Prado bar, analogous to p<0.05) looks structurally unreachable at N=131 trades** - the noise floor is driven by Sharpe variance at this sample size, not search-grid size, and no realistic combo clears it given the layers' documented signal strength (r≈0.22-0.45 correlation, from the overnight-gap accuracy work above). Treat DSR/PSR as a permanent caution label on any P&L-swept combo, not a pass/fail gate; rely on LOOCV out-of-sample total return + the permutation test (both pass cleanly and don't share this ceiling) as the real evidence of validity.
- **News layer has no digest for backfilled (pre-2025) quarters** - out of scope so far; `blend_scores`' missing-layer redistribution handles it automatically (those quarters blend on micro+quant only). Re-sourcing ~107 more quarters was scoped once and found *not* to change the overnight verdict (still wouldn't clear 0.687), so it's deprioritized, not abandoned.
- **Long filings (10-K/10-Q, JPMC supplement) remain excluded by design** - obvious extension point if deeper regulatory context is ever wanted.
