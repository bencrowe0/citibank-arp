# CLAUDE.md

Citibank Applied Research Project - earnings materials in, DeepSeek-powered structured BUY/HOLD/SELL predictions out, calibrated against actual stock price outcomes.

## Architecture

**6 issuers** (`jpm`, `bank_of_america`, `boeing`, `disney`, `target`, `netflix`) across 4 sectors - Financials (JPMorgan, Bank of America), Media/Communication Services (Netflix, Disney), Industrials (Boeing), Consumer/Retail (Target). Four scored layers, blended into one signal:

- **Micro** (`report_pipeline.py`, `run_reports.py`) - the company's own earnings materials (press release + presentation + transcript, bundled into one LLM call per quarter). This is the core layer; everything else adjusts it.
- **Macro** (`llm_macro.py`) - FOMC minutes, scored once per meeting and reused across every company/quarter whose `report_date` falls after that meeting's release (entity-agnostic, cached under `outputs/macro/results/`).
- **News** (`llm_news.py`) - a **pre-earnings market-expectations digest** per company/quarter (`REPORT_TYPE = "Pre-Earnings Market Expectations Digest"`), sourced from free outlets (CNBC, Yahoo Finance) via web search, stored as plain text under `docs/news/<issuer>/<document_id>.txt` with source URLs + publish dates recorded inline for auditability. **Every source article is dated strictly before `report_date`** - this is a hard rule, not a convenience: an earlier version of this layer used an "earnings date and following days" window and leaked actual post-earnings stock-reaction language into the digest text (see "Data leakage fix" below). The layer now scores how stretched or depressed market expectations were heading into the print, not sentiment about results that don't exist yet in the source text. Backfilled (2022-2024) quarters do not have a news digest (see Round 4) - this is a known gap, not a bug.
- **Quant** (`quant_layer.py`) - deterministic, yfinance-only, zero-LLM-cost composite of price momentum, EPS surprise, and a macro-numeric sub-component (`^TNX`, `^IRX`, `^VIX`). Added in Round 4; see below for why it doesn't yet earn blend weight.
- **Blend** (`blend.py`) - weighted sum of the four layer scores into one blended sentiment score, then the same `hold_upper`/`hold_lower` threshold mechanism derives BUY/HOLD/SELL. `DEFAULT_WEIGHTS = (0.8, 0.0, 0.2, 0.0)` (micro/macro/news/quant) as of Round 4 - this is the pooled-LOOCV-selected default, not a hand-tune (see Round 4).

Micro/macro/news share the same prompt (`prompts/llm_analysis_prompt_template.md`), just with a different `{{REPORT_TYPE}}` and `{{REPORT_TEXT}}`. Quant is pure arithmetic, no LLM call.

## Manifest schema

`manifests/<issuer>_reports.json` - each report entry has a `documents` list (not a single `source_pdf`): `[{"doc_type": "Press Release", "source_pdf": "..."}, ...]`. Single-document issuers (Netflix) just have a list of length 1; Disney backfilled quarters use press release + transcript (length 2, no presentation - Disney doesn't file one). `report_pipeline.build_bundle_text()` concatenates a report's documents into one labeled text block per quarter.

Long filings (10-K/10-Q, and for JPMC the earnings release financial supplement) are downloaded and stored under `docs/<issuer>/filings/` but are **intentionally excluded** from every layer's default input - too long/dense, matches the group's "too financy" feedback on the source documents.

## Running the pipeline

See [README.md](README.md) for the micro-layer run commands. For the macro/news/blend/eval pieces:

```powershell
python llm_macro.py                         # score all FOMC minutes (cached, idempotent)
python llm_news.py                          # score all pre-fetched news digests (cached, idempotent)
python quant_layer.py                       # score all quarters' quant composite (free, cached, idempotent)
python blend.py <issuer>                    # blend micro+macro+news+quant for one issuer's quarters
python -m eval.run_eval                     # calibrate threshold + blend weights, pooled across ALL issuers
python -m eval.run_eval --issuers jpm,bank_of_america   # per-sector experiment (see Round 4)
python build_cost_ledger.py                 # rebuild outputs/global/summary/api_cost_ledger.csv from existing artifacts (no API calls)
```

`run_reports.py` also takes `--prompt <file>` (test an alternate prompt template without touching the default), `--ensemble N` (average N repeat runs per document instead of trusting a single call), and `--variant <label>` (writes to `outputs/<issuer>_<label>/` instead of `outputs/<issuer>/`, so an experimental run can never overwrite the canonical one). `python -m eval.run_eval --issuers <issuer>_<label>,...` evaluates a variant folder the same way (macro/news lookups automatically resolve the variant label back to the real issuer name). `compare_runs.py <results_a> <results_b>` prints a side-by-side signal/score diff between any two results folders, optionally scored against a ground-truth CSV. See "Round 3" below for the workflow these were built for.

## Two distinct threshold concepts - do not conflate

- `hold_upper` / `hold_lower` - thresholds on the LLM's **sentiment score** (-1..+1), used to derive a prediction.
- `outcome_upper` / `outcome_lower` (`eval/outcomes.py`) - thresholds on the stock's **actual forward return**, used to derive the ground-truth label a prediction is checked against.

Never reuse the `hold_*` names for the outcome-side threshold or vice versa.

## Known limitations

- **N=78 pooled, still not large.** `eval/run_eval.py` pools all 6 issuers before running leave-one-out cross-validation so the tuned threshold/weights are one shared answer rather than six separately overfit ones. As of Round 4 (see below), pooled LOOCV threshold-only tuned=default=0.51 and blend tuned=default=0.54 - the tuned/default gap that signaled overfitting at N=12/24/33 has closed, and every one of the 78 LOOCV folds now independently selects the same weights as the hardcoded default. This is meaningfully more convincing than earlier rounds but still not a large-N validation.
- **News layer source bias, and now a news coverage gap.** Digests are pulled from a small set of free outlets (CNBC, Yahoo Finance) in a fixed pre-report date window - auditable (source URLs + publish dates recorded) but not a guarantee against selection/outlet bias. Additionally, the 54 quarters backfilled in Round 4 (2022-2024) have **no news digest at all** - re-sourcing a leak-free, pre-earnings digest for 54 additional quarters was out of scope for the backfill session; `blend_scores`' missing-layer redistribution handles this automatically (those quarters blend on micro+quant only), but it means the news layer's sample is smaller and more recent (2025 quarters) than the micro/quant layers.
- **Blend beats micro alone by a modest, now-stable margin.** Pooled LOOCV at N=78: micro-only threshold accuracy 0.51, blend accuracy 0.54 (both default=tuned, unanimous across folds - see Round 4). This is a smaller gap than round-1/round-2's optimistic-but-overfit tuned numbers, but it is the first version of this result that isn't an overfitting artifact.
- **Quant layer does not currently earn blend weight.** Every LOOCV fold at N=78 (see Round 4) picks quant weight = 0.0, same as macro. Kept in the codebase as a tested, honest negative, not removed - matches the project's history with macro/news at earlier N.
- **Per-sector calibration overfits, confirmed at larger per-sector N.** Round 4 re-ran per-sector LOOCV at N=13-26/sector (was N~4-8/sector in the original experiment): Financials (jpm+bac, N=26) shows a real gap (tuned 0.62 vs default 0.54 threshold-only) that could be a genuine sector effect or still overfitting at N=26; Industrials (boeing, N=13) and Consumer/Retail (target, N=13) both show tuning making things *worse* than default (0.31 vs 0.46, and 0.31 vs 0.54) - the textbook overfitting signature. Pooled remains the default methodology; per-sector stays an experiment.
- **Long filings excluded by design.** 10-K/10-Q filings and JPMC's financial supplement are stored but never fed to any layer. If a future phase wants deeper regulatory/financial-statement context, this is the obvious extension point.

## Prediction-accuracy fix (2026-07-02)

First pooled eval run scored **2/12 (16.7%)** - worse than naive always-SELL (50%) or always-HOLD (41.7%) baselines, with a systematic BUY-bias: 11/12 quarters predicted BUY regardless of actual outcome (actual distribution was 50% SELL / 41.7% HOLD / 8.3% BUY - 2025 was a rough year for Boeing/JPM/Netflix).

**Root cause, diagnosed against the actual data**: the prompt's scoring anchors (`prompts/llm_analysis_prompt_template.md`) mapped "solid results, modest beat, stable guidance" to +0.5 - but that description fits nearly every earnings release, so the micro layer (60% blend weight) floored almost every quarter above zero regardless of whether the stock was actually expected to move. The model was scoring "was this a good quarter in isolation" rather than "did forward guidance change relative to what the company itself had previously signaled." News (20% weight) compounded it; macro (20% weight, itself roughly balanced) was too small a weight to correct it.

**Fix applied**: rewrote the scoring-anchor section to make the score track *change in forward guidance versus the company's own prior guidance* rather than absolute quarter quality, with "in-line, modest beat, guidance reaffirmed" explicitly anchored to 0.0 instead of +0.5, plus two in-prompt calibration examples. Also reduced `eval/calibrate.py`'s `WEIGHT_STEP` from 0.1 to 0.2 (66 -> ~21 weight combinations) to shrink the joint search space's overfitting risk at N=12. All micro/macro/news scores were regenerated under the new prompt (old cached results deleted and re-run).

**Result**: prediction distribution is no longer degenerate (was 11 BUY / 0 HOLD / 1 SELL, now 4 BUY / 6 HOLD / 2 SELL - much closer to the actual 1/5/6 split). Pooled LOOCV: **default-weights accuracy 0.42** (was 0.17), **tuned blend-weight+threshold accuracy 0.58** (was 0.17, and previously tuning made things *worse* than default - 0.08 - which is no longer the case now that the underlying scores are properly calibrated). A supplementary run at a 10-trading-day outcome window (vs. the default 5-day) is saved alongside as `outputs/global/summary/global_outcome_calibration_window10.csv` / `global_calibration_summary_window10.json` - default accuracy is lower at that window (0.17) but tuned blend still recovers to 0.50; the 5-day window remains the default methodology, this is reported as a supplementary robustness check, not a replacement.

Still small-N (12 documents) - this is a real, meaningful improvement, not a fully solved problem, and should be presented to the team as directional evidence that fixing the LLM's scoring calibration (not just tuning thresholds after the fact) is what actually moves accuracy.

## Round 2: data leakage fix + further calibration (2026-07-02)

Asked to push accuracy further (target 8-9/12), with an explicit constraint: no shortcuts and no data leakage. Two things were found and fixed before any further tuning was attempted.

**Data leakage found and fixed.** The news digests (built under the round-1 fix above) were fetched from an "earnings date and following days" window. 4 of 12 digests turned out to contain explicit post-earnings stock-reaction language - e.g. "Boeing stock fell 4% on the announcement," "shares of JPM tumbled 1.9% after the release," "shares... declining by up to 12% following the announcement." The news layer (20% blend weight) was partially reading the actual outcome, not predicting it. Some of round 1's reported 7/12 (tuned blend) was leakage-inflated.

Fix: all 12 news digests were rebuilt from scratch using only articles dated **strictly before** `report_date` - pre-earnings analyst estimates, valuation framing, and expectations-setting coverage, sourced and date-verified per article. This redefines the news layer's purpose: it now measures how stretched or depressed market expectations were heading into the print, not sentiment about the print itself. A first pass at rescoring these under the *round-1* prompt scored everything ~0.0 (neutral) because the scoring anchors were built around "did guidance change," which doesn't apply to a document that predates the guidance - the model correctly noted "no guidance in this document" and defaulted to neutral, discarding real signal like "priced for perfection" valuation commentary. A second prompt fix added an explicit interpretation rule for pre-earnings digests: score how stretched (bearish) or depressed (bullish) expectations are, not whether guidance changed. After that fix, news scores became genuinely directional (e.g. all 4 Netflix quarters scored negative, correctly flagging the "stock priced for perfection" pattern the pre-earnings coverage kept surfacing).

**Micro-layer prompt further sharpened** (same file, extending round 1's anchors, not replacing them): explicit instructions to (a) read the earnings-call Q&A section for analyst pushback/management hedges as real signal, not just prepared remarks, (b) discount guidance improvements management itself attributes to FX/one-time/deferred items vs. organic performance, (c) weight structural/recurring risks (e.g. Boeing's 777X durability issue, KC-46A charge) above one-time noise, and (d) a new +0.15/+0.3 middle band for genuine operational momentum (e.g. a real loss-to-profit swing) that hasn't yet produced a formal guidance raise - the round-1 anchors were correctly catching the extremes but conflating "real momentum, no raise yet" with "flat quarter, no raise."

**Result, fully corrected for leakage**: pooled LOOCV lands at **6/12 (50%)**, achieved by the micro-layer signal alone (threshold-only prediction) - this is the current best, honestly-arrived-at number, down from round 1's leakage-tainted 7/12 but up from the original 2/12. The corrected blend (weights + threshold jointly tuned via the same LOOCV machinery, untouched) performs *worse* (3/12) - LOOCV folds kept picking a 100%-news weight that fit the calibration set but did not generalize to the held-out document, the textbook overfitting signature at this N. This is reported honestly rather than hidden: **macro and news do not currently add predictive value over micro alone**, even though the news layer is now genuinely informative and leak-free. `blend.py`'s `DEFAULT_WEIGHTS` (0.6/0.2/0.2) is left unchanged rather than hand-fit to this finding.

**Target of 8-9/12 was not reached.** Per the plan agreed before this round, prompt refinements were required to be justified by an articulable document-reading principle, not "whatever flips this specific row" - and weight/threshold tuning was restricted to the existing LOOCV machinery, not manual overrides. Both constraints were honored. The remaining wrong calls (BA_FQ2, BA_FQ4, NFLX_FQ1_2026, NFLX_FQ2, NFLX_FQ3, NFLX_FQ4) were individually reviewed; all six have document-defensible sentiment scores near the HOLD/BUY boundary that the model can't confidently push further one way without inventing a rule that wouldn't apply to any *other* document - i.e. this looks like the genuine ceiling for a document-grounded, non-leaking predictor at N=12, not a gap the team should expect to close with more prompt engineering on this same 12-document set. Growing N (as the rest of the team's companies land) is the most promising remaining lever.

## Round 3: evaluated a teammate's (Nigel's) fork for ideas (2026-07-02)

Nigel had amended Ben's first push - an earlier commit than round 1/2 above, before the multi-document bundling, BUY-bias fix, or leakage fix existed. Rather than merge his branch (which would have regressed the pipeline), his diff was mined for independently-good ideas, each evaluated on its own merits against the current 6/12 baseline before being adopted. Nothing was merged just because it "didn't hurt" - see the decision rule this round used, kept in `C:\Users\bencr\.claude\plans\nigel-ammended-the-first-ethereal-lerdorf.md`.

**Adopted (infra/correctness, no accuracy claim):** `report_pipeline.py` gained a deterministic `derive_signal()` recompute in `call_llm` - the stored `signal.direction` is now always derived from the score against the fixed thresholds rather than trusted verbatim from the model, with the model's own stated direction kept as `model_stated_direction` and any disagreement flagged as `signal_mismatch` (an audit signal, not something `eval/run_eval.py` depended on - it already recomputed the signal from the raw score independently, so this doesn't change any reported accuracy number). Also added: `validate_result()` (checks required JSON keys before accepting a response), retry-with-backoff in `call_llm`, `cache_hit_tokens()` (trusts DeepSeek's actual `prompt_cache_hit_tokens` over the previous cached-input guess), and a `PromptPack` class plus `--prompt`/`--ensemble`/`--variant` flags on `run_reports.py` so an experimental prompt or setting can be tested into its own `outputs/<issuer>_<variant>/` folder without touching the canonical one. `compare_runs.py` (new file) does side-by-side signal/score diffing between two results folders, optionally scored against a ground-truth CSV - this is what made the two tests below fast to run and audit.

**Tested and rejected: ensemble averaging.** Nigel's `ensemble_llm()` runs a document N times and predicts off the mean score, on the theory that averaging smooths run-to-run noise on boundary documents (round 2 had flagged all 6 remaining wrong calls as boundary cases). Tested with `--ensemble 3` on all 12 documents under the unchanged round-2 prompt (`outputs/<issuer>_ensemble3/`). Result: pooled LOOCV threshold-only accuracy **dropped to 0.33 (4/12)**, from baseline 0.50 (6/12). Per-document diff (`compare_runs.py`, then cross-checked against `eval/outcomes.py`'s independent score-vs-threshold recompute): the 3-run mean nudged three already-near-the-0.15-boundary scores *upward* - JPM_FQ2 (0.15→0.167), JPM_FQ3 (0.15→0.183), NFLX_FQ1_2026 (0.15→0.2) - flipping two previously-correct HOLD calls (JPM_FQ2, JPM_FQ3) into wrong BUYs, with no compensating correct flips anywhere else. The nudges were consistently upward across every affected document, not randomly distributed, which argues against "just noise cancelling out" being a reliable mechanism at this N and this close to the threshold. **Rejected** - `ensemble_llm`/`--ensemble` stay in the codebase as a tested, available option (e.g. for future prompts that aren't sitting exactly on the boundary), but are not used in the default run.

**Tested and rejected: "surprise vs. expectations" prompt reframing.** Nigel's separate `llm_reaction_prompt_v2.md` draft scores the document as a forecast of surprise-driven market reaction rather than "change in the company's own forward guidance." A merged version (`prompts/llm_reaction_prompt_v2_merged.md`) was written combining that reframing with the round-2 anchors (organic-vs-attributed, Q&A pushback, structural-vs-one-time risk, pre-earnings-digest handling, all kept unchanged) rather than testing nigel's file verbatim, since those round-2 refinements are compatible with a surprise-based framing, not a replacement for it. Tested single-run (no ensembling) on all 12 documents (`outputs/<issuer>_v2prompt/`). Result: pooled LOOCV threshold-only accuracy **dropped to 0.33 (4/12)**. Per-document diff showed a systematic *upward* score shift versus the round-2 prompt on almost every document (e.g. BA_FQ2 0.25→0.30, JPM_FQ2/JPM_FQ3 0.15→0.20, NFLX_FQ1_2026 0.15→0.25) - the same two JPM boundary docs flipped wrong, plus NFLX_FQ1_2026 also flipped HOLD→BUY (wrong; actual outcome SELL), with no new correct calls anywhere. In effect, despite v2's own explicit anti-BUY-bias language ("in-line documents should score near zero even when results are strong"), the surprise framing combined with round-2's anchors still produced a mild version of the exact BUY-bias round 1 had to fix. **Rejected** - the merged prompt file is left in the repo as a tested, documented dead end (in case a future prompt iteration wants to revisit the surprise framing with a different anchor calibration), but the default prompt (`prompts/llm_analysis_prompt_template.md`) is unchanged.

**Net result: the round-2 baseline (6/12, micro-only threshold prediction) is still the best result and is unchanged.** Both scoring-affecting ideas from Nigel's fork were tested honestly against the pooled-LOOCV harness and both underperformed with no tie-breaking argument in their favor, so per this round's decision rule neither was adopted. The infra improvements (signal-mismatch auditing, retry/validation robustness, accurate cache-hit cost accounting, and the `--prompt`/`--ensemble`/`--variant`/`compare_runs.py` A/B-testing toolchain) are kept regardless, since they were justified on correctness/tooling grounds independent of this outcome. Full experiment artifacts (extra output folders, saved eval summaries) are kept under `outputs/*_ensemble3/`, `outputs/*_v2prompt/`, and `outputs/global/summary_comparisons/` for audit.

## Round 4: quant layer, backfill to N=78, per-sector re-check, cost ledger (2026-07-08)

Four things were requested this session: a new free quantitative layer, scaling N by backfilling earlier quarters, a per-sector vs. pooled re-check, and API cost tracking - all without overfitting or leakage. `bank_of_america` was added as a 6th issuer alongside the existing 5 (jpm, boeing, netflix, disney, target), matching CLAUDE.md's already-updated (but previously undocumented) issuer count.

**Quant layer added** (`quant_layer.py`, new file): deterministic, yfinance-only, zero-LLM-cost. Composite of price momentum (trailing return into the print), EPS surprise (from `get_earnings_dates`), and a macro-numeric sub-component (`^TNX`, `^IRX`, `^VIX` levels as of `report_date`) - all collapsed into **one** `quant` score via a fixed formula (not one tunable weight per metric), so it adds exactly one blend dimension, same overfitting-control discipline as macro/news. Wired into `blend.py`/`eval/calibrate.py`/`eval/run_eval.py` as a 4th layer with default weight 0.0 (verified byte-for-byte identical blend behavior when quant weight is 0).

**Backfill: JPM + 5 more issuers, 2022-2024, N 24 -> 78.** Two prior sessions had failed to backfill via background subagents (misread the task once, then hit the weekly usage limit after spawning uncontrolled child agents against explicit instructions) - this round's backfill was done **inline in the main thread**, no subagents, matching the lesson learned. For each issuer, 9 quarters (FQ4 2022 through FQ4 2024) were added the same way: real report dates from `yfinance.get_earnings_dates()`, official sources found via web search (SEC EDGAR 8-K exhibits for press releases/presentations where filed, company IR CDN PDFs for presentations/transcripts where SEC doesn't carry them, Motley Fool/Insider Monkey for call transcripts as a free fallback when a company doesn't file one), every document downloaded and verified with `report_pipeline.extract_doc_text()` (must extract AND contain the correct year token - nothing was fabricated or accepted unverified), then scored via a temporary issuer-only manifest and merged into the canonical `manifests/<issuer>_reports.json`.

Backfilled per issuer: JPM (prior session, 9 quarters, $0.087), Bank of America (9 quarters, $0.165), Boeing (9 quarters, $0.081), Disney (9 quarters, $0.084), Target (9 quarters, $0.089), Netflix (9 quarters, $0.052). Total backfill LLM cost this session: **~$0.47**. Verification caught two real mistakes before they entered the manifest: a Boeing SEC accession that turned out to be a CEO-succession 8-K rather than the earnings 8-K (wrong document, same filing date - caught because the extracted text read "Boeing Board Names Kelly Ortberg..." instead of "Boeing Reports..."), and a Target stray-download folder-naming scheme left off-by-one by an earlier failed agent run (fixed by renaming to match the fiscal-period-based convention used elsewhere, not the report date's calendar quarter).

Backfilled quarters get **micro + quant only** (no news digest - re-sourcing 54 leak-free pre-earnings digests was out of scope this round; `blend_scores`' existing missing-layer redistribution handles this automatically) and **no macro** for dates the existing FOMC manifest doesn't cover. Disney's backfilled quarters use press release + transcript (2 docs) rather than the 2025-quarters' transcript-only pattern, since Disney's SEC 8-K exhibits include an official press release that adds real grounding - documented as an intentional, not accidental, inconsistency in per-quarter document composition (the manifest schema already supports variable-length `documents` lists per quarter).

**Result at N=78**: pooled LOOCV threshold-only **default=tuned=0.51** (was 0.55 default at N=33, and diverging from tuned at smaller N); blend **default=tuned=0.54**. The overfitting signature from every earlier round (tuned beating default on the calibration set, then failing to generalize) has disappeared: inspecting all 78 LOOCV folds' tuned weights individually shows **every single fold independently selects the exact hardcoded default (0.8/0.0/0.2/0.0)** - not a coincidence at this point, a genuine convergence. Quant still does not earn weight (same as macro), consistent with the project's honest history of macro/news not adding measurable value at these sample sizes - reported as a stable negative, not hidden.

**Per-sector re-check at larger per-sector N** (still an experiment, pooled remains default): Financials (jpm, bank_of_america; N=26) - threshold tuned 0.62 vs default 0.54, blend tuned 0.62 vs default 0.58 - a real gap that could be a genuine sector effect at N=26 or still overfitting; worth re-checking as Financials grows further. Media/Communication Services (netflix, disney; N=26) - threshold and blend both converged (tuned=default=0.50 and 0.54 respectively) - no overfitting gap, but no lift either. Industrials (boeing; N=13) and Consumer/Retail (target; N=13) both show tuning actively *hurting* (0.31 tuned vs 0.46/0.54 default) - the same overfitting signature the pooled default is designed to avoid, now visible at a larger N than the original per-sector experiment.

**Cost ledger built** (`build_cost_ledger.py`, new file): aggregates the per-call cost logs `run_reports.py`/`llm_macro.py`/`llm_news.py` already wrote into every result artifact, into one CSV (`outputs/global/summary/api_cost_ledger.csv`). Deliberately built as a **read-only aggregation script**, not a live per-call hook wired into the three scoring scripts - re-running it after any future scoring run picks up new cost data with zero additional API calls or code-path risk, which was judged the better tradeoff for a research pipeline over adding a shared `record_cost()` call site to three files for a modest interface convenience gain. Total logged cost across all layers to date: **~$0.68** (micro $0.557, news $0.065, macro $0.055; quant is free and not logged).

**`data/backfill_provenance.csv` filled** (122 rows: one per backfilled document, across all 6 issuers) with `source_url`, verification `status`, and a note confirming the extract-and-year-token check. A few rows note "exact URL not logged that session" for documents downloaded by earlier stray/failed-agent attempts before this round's URL-tracking discipline was in place, rather than fabricating a URL after the fact.

**Finer-grained pooled weight/threshold search (same session, follow-up ask).** The coarse production grid (`WEIGHT_STEP=0.2`, 6 threshold candidates, 336 total combos) was re-checked with a much finer exploratory grid (`WEIGHT_STEP=0.05`, 18 threshold candidates spanning 0.05-0.40, 31,878 total combos - not committed to `eval/calibrate.py`, run as a standalone script to avoid raising the production overfitting-risk surface). Two results: (1) the **global best-fit** (fit on all 78 documents, no held-out fold - the literal "best possible on this data") is accuracy **0.5385 (42/78)**, achieved by weights **(0.8, 0.0, 0.2, 0.0)** at threshold **±0.25** - exactly the existing hardcoded default (2 other combos tie the same accuracy, both still macro=quant=0, both losing the tie-break to "closest to default"). (2) **LOOCV at that same finer grid** gives tuned=default=**0.5385 across all 78 folds**, unanimous. This confirms the coarse-grid convergence reported above isn't a grid-resolution artifact - searching ~95x more combinations lands on the identical answer. Macro and quant contributing exactly zero weight is a real property of this data at N=78, not a search-resolution limitation; the only remaining lever to move this number is more data or a different scoring approach, not finer tuning.

**Not done this round** (explicitly deferred, not forgotten): re-sourcing news digests for the 54 backfilled quarters; a `data/quantitative/` replication-friendly folder layout for cached yfinance pulls (quant_layer.py currently re-fetches from yfinance each run rather than caching to disk). All are natural next steps if N keeps growing.
